# RFP Requirements Summary

This summary translates the RFP into build requirements. The full extracted RFP text is in `data/rfp_text.txt`, and the source DOCX is included at package root.

## Required outcomes

- Visual overhaul aligned to current brand/design direction.
- Simplified structure and faster access to information.
- Cohesive service to multiple audiences: ticket buyers, venue guests, arts mission audiences, donors, volunteers, educators, partners, press, staff, and job applicants.
- Conversion-focused landing pages.
- Flexibility for one-off experience pages.
- Reduced contact requests through clearer self-service content.
- Increased engagement and click-through to organizational outcomes.
- Excellent desktop and mobile experience.

## Required scope

- 7 templates: Home/Events, Landing Page, Plan Your Visit, Story Hub, Pop Over CTA, Event Details Page, Blank/Flow.
- Approximately 30 pages, plus a backlog of historical event pages and blog/story content.
- Responsive and accessible implementation.
- Backend accessible to Pavilion staff.
- Content editing should not require frequent developer involvement.

## Functional needs

- Event listings and event detail pages.
- HubSpot form integration.
- Ticketmaster/Account Manager integration for Season Seat holders.
- AI search functionality.
- Easy video hosting or embedding.

## Content and migration assumption

The Pavilion team intends to provide and port content. The build should therefore include content models, fixtures, and editing workflows, but should not require final production content to be available before template implementation.

## Technical requirements

- CMS/platform is not preselected.
- Vendor-hosted or deployable hosting path should be documented.
- LLM or similar AI tool is desired for fan-question responses.
- Existing external platforms include HubSpot, Foundant, DonorPerfect, and Acceptd.

## Timeline context

The RFP targets a mid-March start and July completion. Codex should structure the build in phases so templates, content modeling, integrations, and QA can be reviewed progressively.

## Rubric implications for build quality

The eventual implementation will be judged by:

- understanding of organizational goals and audience balancing;
- cost/value/timeline clarity;
- CMS and integration fit;
- UX, accessibility, and responsive design quality;
- relevance to arts, entertainment, nonprofit, or ticketed event needs.
