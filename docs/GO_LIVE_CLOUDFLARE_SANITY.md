# Cloudflare + Sanity Go-Live Runbook

## Current Production Architecture

- Public site: static HTML generated by `npm run build`.
- CMS: Sanity project `y8zl4q1a`, dataset `production`.
- Recommended host: Cloudflare Pages.
- Publish automation: Sanity webhook calls a Cloudflare Pages Deploy Hook.
- CRM/forms: HubSpot forms and optional HubSpot tracking.
- Analytics: Google Tag Manager preferred, GA4 direct fallback supported.

## Git Remote Setup

Create an empty repository in GitHub, GitLab or your preferred Git host. Do not initialize it with a README if it asks.

Then connect this local project to that remote:

```sh
git remote add origin GIT_REPO_URL
git push -u origin staging
```

For example, if the repo were on GitHub:

```sh
git remote add origin git@github.com:woodlandscenter/cwmp-redesign.git
git push -u origin staging
```

After the push, connect Cloudflare Pages to that Git repository and choose the `staging` branch.

## Sanity Publish Automation

## Sanity Access

To grant setup access:

1. Open Sanity Manage.
2. Select project `y8zl4q1a`.
3. Go to **Members**.
4. Invite the setup user by email.
5. Assign **Administrator** or a custom role that can manage API/webhooks.

Administrator access is needed only for the deploy webhook setup. After the webhook is confirmed, the role can be reduced to the normal editor/admin level your team prefers.

In Cloudflare Pages:

1. Open the Pages project.
2. Go to **Settings > Builds > Deploy hooks**.
3. Add deploy hook:
   - Name: `Sanity Production Publish`
   - Branch: `staging` for the first staging deployment
4. Copy the generated deploy hook URL.

In Sanity project `y8zl4q1a`:

1. Go to **API > Webhooks**.
2. Add webhook:
   - Name: `Cloudflare Pages Production Deploy`
   - Dataset: `production`
   - URL: Cloudflare Deploy Hook URL
   - HTTP method: `POST`
   - Trigger on create/update/delete/publish events.

Recommended GROQ filter:

```groq
_type in [
  "event",
  "planVisitTopic",
  "mission",
  "seasonSeats",
  "grantProgram",
  "outreachProgram",
  "landingPage",
  "story",
  "storyTopic",
  "navigation",
  "alert",
  "blocks",
  "forms",
  "settings",
  "externalRoutes"
]
```

Success criterion: publishing a harmless Sanity edit starts a Cloudflare build and the live page updates after the build finishes.

## Analytics and CRM

The site shell supports:

- `GTM_CONTAINER_ID`: injects Google Tag Manager.
- `GA4_MEASUREMENT_ID`: injects GA4 directly only when GTM is not configured.
- `HUBSPOT_TRACKING_MODE=direct`: injects HubSpot tracking script directly when `HUBSPOT_PORTAL_ID` is configured.

Recommended event names pushed to `dataLayer`:

- `get_tickets_click`
- `parking_click`
- `lawn_chair_click`
- `hotel_click`
- `bag_policy_click`
- `plan_visit_search`
- `mission_signup_click`
- `event_card_click`
- `story_filter`
- `hubspot_form_load`
- `hubspot_form_submit`
- `hubspot_form_fallback`
- `cta_click`

Do not configure GTM/GA4 tags to collect names, emails, phone numbers or raw form field values.

## Launch Checklist

Before staging review:

- Confirm Cloudflare Pages production build succeeds.
- Confirm Sanity publish triggers Cloudflare deploy.
- Confirm HubSpot forms submit into the correct lists/workflows.
- Confirm GTM Preview sees the listed events.
- Confirm GA4 DebugView receives events without PII.
- Confirm all external CTA URLs are final.
- Confirm `preview.woodlandscenter.org` is password protected.
- Add any required legacy redirects to `cloudflare/_redirects`.
- Run `npm test`.
- Run one rollback drill in Cloudflare Pages.

After staging is approved and DNS cutover is scheduled:

- Verify apex and `www` behavior.
- Verify HTTPS.
- Verify homepage, Events, Event Detail, Plan Your Visit, Mission and Story Hub.
- Submit one test HubSpot form.
- Confirm GA4 realtime traffic.
- Publish one harmless Sanity edit and verify live update.
